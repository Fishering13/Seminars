# Seminars

Семинары по алгоритмизации и программированию. C++17, Visual Studio Code + WSL Ubuntu, CMake.

## Структура

- `SEMINARS/Семинар_1` … `SEMINARS/Семинар_4` — исходные коды прошлых семинаров, сохранены без изменений.
- `SEMINARS/Seminar_5` — линейный, двоичный поиск и поиск по 256 корзинам.
- `SEMINARS/Seminar_6` — шесть порядков циклов умножения матриц.
- `results` — исходные измерения, медианы, графики и протокол проверок.
- `.vscode/tasks.json` — сборка и запуск отдельных программ в VS Code.

Отчеты хранятся локально, в репозиторий не включены.

## Открытие и сборка

Рабочая копия на этом компьютере: `/home/fisher/projects/Seminars`.
Открыть ее в VS Code: **File → Open Folder** в окне WSL либо из WSL:

```sh
cd ~/projects/Seminars
code .
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

В VS Code `Ctrl+Shift+B` запускает сборку. **Tasks: Run Task** → `Run linear`, `Run binary`, `Run buckets` или `Run matrix_benchmark` запускает программу.

## Семинар 5

Заготовки: https://github.com/studymaterials2026/student, исходная ветвь master.
Реализованы `find_linear`, `find_binary`, `build_buckets`, `find_in_buckets`.
Генерация, алгоритм замеров и валидация параметров сохранены; изменены форматирование и пояснения типов в справке.

```sh
./build/linear --size 1000000 --queries 1000 --seed 42 --hit-rate 0.5
./build/binary --size 1000000 --queries 1000 --seed 42 --hit-rate 0.5
./build/buckets --size 1000000 --queries 1000 --seed 42 --hit-rate 0.5
```

`--size` и `--queries` — положительные целые `uint64_t`; `--seed` — неотрицательное целое `uint64_t`; `--hit-rate` — вещественное `double` от 0 до 1. Клавиатурный ввод не требуется. Справка: `--help`.
На одинаковых данных все программы находят 500 из 1000 запросов. Дополнительно проверены доли 0 и 1, пустые массивы, границы, дубликаты и коллизии корзин.

## Семинар 6

```sh
mkdir -p results
cd results
../build/matrix_benchmark
```

Автоматический эксперимент без ввода: малые n=20,36,52,68,84; средние n=100,150,200,250,300; большие n=500,525,550,575,600. n — порядок квадратной матрицы (n² элементов). Все шесть порядков выполняют `A += B*C` на отдельных матрицах, хранящихся построчно в `vector<double>`; в опыте A предварительно обнуляется.

Пять повторов на каждую пару размера и порядка, 450 замеров. `steady_clock`, генерация и обнуление вне замера. Контроль поэлементного равенства и контрольная сумма исключают удаление вычислений оптимизатором. Входные целые значения от -3 до 3 точно представимы в double; seed=42. Варианты запускаются с циклическим сдвигом порядка. Медианы и три отдельных графика по группам размеров находятся в `results`.

Замеры: Intel Core i5-11400H, WSL Ubuntu, GCC 15.2.0, CMake Release `-O3 -DNDEBUG`. При n=600 медиана ijk=0.239806247 с, ikj=0.056420182 с (примерно 4.25 раза быстрее). На другой нагрузке и оборудовании время изменится.

Быстрая проверка: `./build/matrix_benchmark --quick` (n=1,2,3,10). CSV всегда записывается в текущую папку; при повторном запуске заменяет предыдущий файл с тем же именем.

## Воспроизведение проверки и графиков

```sh
python3 verify.py
python3 -m pip install matplotlib
python3 analyze.py
```

`verify.py` проверяет поиск на обычных и граничных случаях; затем сверяет все порядки матриц на малых размерах. `analyze.py` читает `results/matrix_timings.csv`, сохраняет медианы и PNG-графики.
